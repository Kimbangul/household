# 기간은 지출 날짜 기준으로 자동 매핑되며, 겹치는 것도 허용한다

일반적인 가계부 앱은 정산 주기(기간)를 서로 겹치지 않는 고정 구간으로 다루고, 지출을 특정 기간에 명시적으로 소속시킨다. 이 앱은 반대로 설계했다: "기간"은 사용자가 자유롭게 추가하는 날짜 범위(뷰)일 뿐이고, 지출내역은 기간과 독립적으로 저장되며, 화면에 표시될 때 지출 날짜가 그 기간의 범위 안에 있는지로 자동 집계된다. 기간끼리 겹치는 것도 막지 않는다 — 사용자가 "이번 달"과 "이번 주" 같은 서로 다른 관점의 기간을 동시에 만들어 볼 수 있어야 하기 때문이다. 그 결과 하나의 지출이 여러 겹치는 기간에 동시에 집계되는 것은 정상 동작이다.

이 결정은 되돌리기 어렵다 — 지출을 기간에 직접 귀속시키는 모델로 바꾸려면 데이터 구조와 화면 로직을 다시 짜야 한다. 또한 일반적인 가계부 앱과 다른 선택이라, 나중에 "왜 기간이 겹칠 수 있지?"라는 의문이 생길 수 있는 지점이다.
